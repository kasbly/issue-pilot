DIMENSION: i18n — the product must work in every shipped language.

Hunt for: hardcoded user-facing strings outside the translation system; translation
keys present in one locale and missing in another; concatenated sentences that break
under different word orders; dates, numbers, and currency formatted without locale
awareness; RTL-hostile CSS (left/right instead of logical start/end, hardcoded
directions) if the project ships an RTL locale; untranslated emails, errors, and
empty states — the strings teams forget.

Method: diff the locale files against each other for key drift, then grep rendered
components for literal strings. For RTL, read layout CSS with "what flips?" in mind.

Every issue: the exact string or key, where it surfaces to users, file:line, and the
fix (new key, logical property, locale-aware formatter).
